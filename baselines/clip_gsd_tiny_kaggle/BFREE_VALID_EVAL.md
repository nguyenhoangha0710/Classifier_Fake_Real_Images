# GSD checkpoint → B-Free validation IDs (GPU)

File: `test_gsd_uploaded_best_bfree_valid_kaggle.ipynb`, generated by
`build_bfree_valid_notebook.py`. Runtime: `evaluate_bfree_valid.py`.

Two inputs: trusted current augmented GSD checkpoint and
`baopv051/b-free-training-data` (same contents as version2 audited 2026-10-23).
Previous B-Free Output is a third input only for cross-session continuation.
GPU and Internet are required for the original pretrained CLIP semantic anchor.
No Tiny-GenImage dataset or its manifest is used. The notebook is self-contained.

## Fixed protocol

- Official valid_list.csv MD5: 72e7b4be2d049029dbedca7e75af91b0, 10,304 unique12-digit IDs.
- Master train_list.csv MD5: 06581da53bf81741501396d71eb7ec5f, 51,517 IDs; it includes
  all valid IDs. Used ONLY as a metadata cross-check; no training is performed.
- Full default requests all six SD2.1 branches, each against the same10,304 COCO real
  sources. 20,608 balanced predictions per branch,72,128 unique images,123,648 score
  rows across all branches because real inference is repeated under branch-specific bases.
- Deterministic ID order uses hash(['bfree_valid',42,COCO_ID]). Real then fake for each
  ID; four complete pairs per logical batch8. Same four IDs across corresponding
  batches in every branch. This is OUR declared GSD batch protocol, not the B-Free paper's.
- Original checkpoint architecture, FP16/SDPA/Gram-eigh, original pretrained frozen
  anchor, full detector state loaded strictly, microbatch1, no training or calibration.
- Native RGB, crop cap560, edge-pad14. B-Free512 becomes518 (37x37 patches +CLS=1,370
  tokens), without image resampling or504 crops. No JPEG/resize/blur robustness cases
  are added: the six branches are dataset construction variants, not test processing.
- Fixed0.5 threshold, positive=fake. Report each balanced branch plus macro mean.
  Do not report a pooled1:6 real/fake accuracy as the main result. Do not interpret
  repeated real scores or six derivatives of one COCO ID as independent observations.

## Preparation, resume and output

Resolve the dataset root without walking all image directories. Support single and
double nested image folders. Check membership in both lists and fail on bad checksum,
duplicate IDs, category mismatch, missing member, non-PNG or wrong dimensions.
Only PNG headers and file sizes are read before inference. Full RGB decode happens in
the image loader and errors are surfaced, not silently dropped. This is NOT a full
content/pixel hash audit; same-size image edits can evade metadata provenance, so keep
the identical data version across resumed runs.

The checkpoint finder excludes the B-Free dataset and scans other dataset mount roots
to a bounded depth for best.pt/pth/zip or an unpacked PyTorch folder. Restricted
weights_only=True deserialization is reused from the uploaded-checkpoint evaluator.
Explicit checkpoint_path resolves ambiguous or deeply nested layouts.

Default9.5h soft GPU budget, no branch-count cap. Write raw logits, margins, softmax
scores and batch/token/ID metadata in atomic complete-batch shards every10 batches.
Also flush pending completed batches on planned stop or soft exception. A hard kill
may lose unflushed rows; durable preservation depends on Kaggle actually saving Output.
Completed branches immediately export predictions_BRANCH.csv, metrics.csv and a
macro_metrics.csv with all_branches_complete flag. Partial rows are isolated from
full branch metrics. Combined predictions.csv never deduplicates real context scores.

Cross-session continuation requires attaching saved B-Free Output. Auto chooses the
matching checkpoint/cohort/protocol/environment fingerprint with most saved rows.
No GPU/TPU, GenImage/B-Free, smoke/full, data-version or precision score mixing.
Restore only complete contiguous shards and validate metadata, IDs, labels, branch,
batch IDs, raw logits/probabilities, margins and token geometry before reuse.

SMOKE_ONLY=False is the notebook default. Explicit True uses four valid IDs, all six
branches and a separate output directory; it is not evidence of full validation performance.

Source: https://github.com/grip-unina/B-Free/tree/main/training_data
The checkpoint has not been fine-tuned on B-Free in this workflow. Call the result
cross-dataset evaluation on B-Free's validation split, not an official test benchmark.

Local CPU unit tests validate manifests/checksums, paired batches, image processing,
cache isolation/validation, time pauses and resumption, and notebook generation.
Actual pretrained CUDA inference on the full B-Free corpus is not verified locally.
